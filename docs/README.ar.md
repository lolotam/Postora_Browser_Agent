# Postora Browser Agent — إكستنشن كروم بيتحكم في البراوزر بالذكاء الاصطناعي

وكيل بيشتغل من اللوحة الجانبية (Side Panel) في كروم. بتديله مهمة بالعربي أو الإنجليزي، فينفذها خطوة بخطوة في البراوزر بتاعك (بحث، ضغط، كتابة، اختيار من قوائم، سكرول، تنقل بين التابات، قراءة وتجميع معلومات)، وفي الآخر بيديك **تقرير نهائي** فيه النتايج والمصادر.

## المزوّدين المدعومين

| المزوّد | طريقة الدخول | ملاحظات |
|---|---|---|
| **اشتراك ChatGPT** (Plus / Pro / Business) | تسجيل دخول بحساب ChatGPT **برمز الجهاز** | يظهر رمز مؤقت في اللوحة تكتبه في صفحة التفعيل، أو تستورد `auth.json` من Codex CLI |
| **Claude** (Pro / Max) | تسجيل دخول بحساب Claude **بلصق الرمز** الذي يظهر في Claude بعد الموافقة، أو مفتاح Anthropic API | تفتح الإضافة claude.ai، وتوافق على الطلب، ثم تنسخ الرمز وتلصقه في اللوحة |
| **Grok** (SuperGrok / X Premium) | تسجيل دخول بحساب Grok **برمز الجهاز**، أو مفتاح xAI API | يعمل مفتاح xAI عبر الإعداد المسبق xAI. ⚠️ لم يُتحقق بعد من مسار حساب Grok على حساب حقيقي |
| **MiniMax** | مفتاح API: إعداد للدفع حسب الاستخدام، وإعداد لـ Coding Plan (مفاتيح `sk-cp-`) | لكل منهما مفتاح خاص، والموديل الافتراضي `MiniMax-M3.1-Flash` |

نفس قايمة المزوّدين دي متاحة للمزوّد الاحتياطي. بعد ما تحط المفتاح، زرار ↻ بيحمّل كل موديلات المزوّد مع بحث.

**زرار "اختبار الاتصال"** موجود عند الموديل الأساسي والاحتياطي والطبقة السريعة واحتياطيها. بيبعت طلب حقيقي بنفس الأدوات والإعدادات اللي المهمة بتستخدمها، فبيكشف المفتاح الغلط والموديل اللي ما بيدعمش الأدوات قبل أول مهمة. الزرار بيبقى أخضر لو نجح، وأحمر برسالة المزوّد نفسها لو فشل. قايمة OpenRouter بتعرض بس الموديلات اللي بتدعم الأدوات (tool calls)، لأن الوكيل بيشتغل بيها.

**المفتاح بيتحط مرة واحدة لكل مزوّد:** لو حطيت مفتاح OpenRouter في الموديل الأساسي، الاحتياطي والطبقة السريعة (الأساسية والاحتياطية) بياخدوه أوتوماتيك لما تختار OpenRouter. OpenCode Zen وGo بيستخدموا نفس مفتاح حساب OpenCode. الـ Custom بس مفتاحه خاص بيه لأن كل سيرفر مختلف. وتسجيل الدخول للحسابات والاشتراكات (ChatGPT / Claude / Grok) موحد للتطبيق كله.

**رأيك وتقييمك:** زرار 💬 في الهيدر بيفتح خانة اقتراح بنجوم وإيميل اختياري. وبعد كل مهمة بتظهر 5 نجوم لحد ما المستخدم يقيّم (أو يقفلها 3 مرات). 5 نجوم بتعرض زرار "قيّمنا في متجر Chrome" (لو الإضافة متثبتة من المتجر)، وأقل من كده بتطلب اقتراح. الرسايل بتوصل إيميل صاحب الإضافة عن طريق Formspree، وفيها النص والتقييم ونسخة الإضافة بس، من غير محتوى الصفحات.

**تسجيل الدخول بجوجل (اختياري):** زرار الحساب في الهيدر بيفتح نافذة جوجل (`chrome.identity.launchWebAuthFlow`)، والمستخدم يختار أي حساب. الإضافة بتاخد الاسم والإيميل والصورة بس، وبتعرض الصورة في الهيدر، والاقتراحات بتتبعت بإيميله أوتوماتيك. مفيش سيرفر ولا client secret: جوجل بيرجّع `id_token` لعنوان `https://bhoimdlegicacjkholpfcokajpiimbcn.chromiumapp.org/` اللي الإضافة دي بس بتستقبله. طول ما مشروع Google Cloud في وضع Testing، اللي يقدر يسجّل هما الـ Test users بس.

**لغة ردود الوكيل:** من الإعدادات. لما تكون مقفولة، الوكيل بيرد بنفس لغة المهمة. لما تفتحها لازم تختار لغة (العربية أو English)، والوكيل بيرد بيها دايماً.

## ⚡ الطبقة السريعة (اختياري)

[Jev](https://typesafe.ai) موديل "System One": **ما بيكتبش نص خالص**. بيستقبل حالة الصفحة وأسئلة محددة، ويرجّع اختيارات بالاحتمالات في أقل من ثانية. علشان كده بنحطه **طبقة قبل الـ LLM**:

1. في كل خطوة، Jev بيتسأل سؤال واحد فيه: العملية الجاية (ضغط / كتابة / Enter / سكرول / رجوع / خلصت / محتاج تفكير)، والعنصر، والنص، وهل الهدف اتحقق، وهل الخطوة حساسة.
2. **لو واثق والخطوة آمنة** → بتتنفذ فورًا من غير ما الـ LLM يتنادى (⚡ في الواجهة).
3. **لو مش واثق، أو الخطوة حساسة، أو محتاجة كتابة نص جديد أو تحليل** → الخطوة بتروح للـ LLM، ومعاها ملخص اللي Jev عمله والاختيارات مترتبة بالاحتمالات، فالـ LLM يقرر أسرع.
4. لما Jev يحس إن المهمة خلصت، الـ LLM بيتأكد ويكتب التقرير النهائي (Jev ما بيكتبش).

**المزوّد:** من الإعدادات تختار مين يجاوب أسئلة الطبقة السريعة، وتحط الـ API key والموديل:

| المزوّد | Base URL | الموديل الافتراضي | أقل ثقة للتنفيذ |
|---|---|---|---|
| TypeSafe Jev | `https://api.typesafe.ai` | `jev-latest` | 0.6 |
| Vercel AI Gateway | `https://ai-gateway.vercel.sh/v1` | `typesafe-ai/jev` | 0.6 |
| OpenCode Zen | `https://opencode.ai/zen` | `jev-1.13` (أو `jev-1.13-free`) | 0.6 |
| OpenRouter | `https://openrouter.ai/api` | `typesafe/jev-1.13` (أو `~typesafe/jev-latest`) | 0.6 |

القايمتين (الأساسي والاحتياطي) فيهم نفس المزوّدين دول بس، لأنهم الوحيدين اللي عندهم Jev. OpenCode Zen وOpenRouter بيقدّموا Jev بنفس واجهة TypeSafe (`/v1/systemone`). OpenRouter ما بيعرضش موديلات Jev في قايمة `/models` بتاعته، فالإضافة بتعرض الاتنين ثابتين. قايمة Vercel بتعرض الـ decision models بس، وزرار ↻ بيحدّثها.

**بعد 3 تسليمات ورا بعض للـ LLM** من غير ولا خطوة سريعة، الطبقة السريعة بتقف 3 أدوار للـ LLM (أو لحد ما الصفحة تتغيّر)، عشان مهام القراءة والمقارنة ما تتأخرش بطلبات Jev مش هتتنفّذ. وفي التاب الجديد أو صفحات `chrome://` بتسلّم للـ LLM من غير رسالة.

لو كتبت في Vercel اسم موديل محادثة عادي من "موديل آخر"، بيتسأل نفس الأسئلة في طلب JSON واحد لكل خطوة، واحتمالاته بتبقى **تقدير الموديل نفسه** مش معايرة زي Jev، فارفع "أقل ثقة للتنفيذ" لـ 0.75.

**الوضعين:**
- `auto`: تنفيذ تلقائي للخطوات الواثقة + اقتراحات.
- `hints`: اقتراحات للـ LLM بس. أأمن، بس أبطأ.

**حدود لازم تعرفها:**
- Jev بيكتب **بس** النصوص اللي انت كاتبها بين علامات تنصيص في المهمة (`"..."` أو `«...»` أو `“...”`)، أو اللي الـ LLM كتبها قبل كده. أي نص جديد بيروح للـ LLM.
- Jev ما بيكتبش أبدًا في حقول الباسورد، ولا بينفذ خطوة شكلها حساس (دفع، إرسال، حذف، تسجيل دخول).
- بعد 8 خطوات سريعة ورا بعض، الـ LLM لازم يراجع.
- لو Jev فشل 3 مرات، الطبقة بتقفل نفسها وبيكمل الـ LLM لوحده.
- Jev متدرّب أساسًا على الإنجليزي (English-first)، فالمهام والمواقع العربية ممكن ثقته فيها تبقى أقل، وبالتالي تتحول للـ LLM أكتر.
- لما الطبقة تبقى شغالة، نص الصفحة وقائمة عناصرها بيتبعتوا للمزوّد اللي اخترته (TypeSafe أو البوابة)، زي ما بيتبعتوا للـ LLM بالظبط.
- Jev محتاج TypeSafe API key من [console.typesafe.ai](https://console.typesafe.ai). التسجيل كان متوقف مؤقتًا بسبب الضغط في سبتمبر 2026.

## مزوّد احتياطي

لو المزوّد الأساسي وقف في نص المهمة (خلص الاشتراك أو الرصيد، المفتاح اترفض، السيرفر وقع، أو مفيش اتصال)، المزوّد الاحتياطي اللي تختاره في الإعدادات بيكمّل **نفس المهمة** من مكانها: بيستلم المهمة والخطوات اللي اتعملت وآخر حالة للصفحة، وما بيعيدش اللي خلص. المهمة الجاية بتبدأ على الأساسي تاني.

- بيظهر شريط **أحمر** تحت الهيدر فيه السبب بلغة واضحة ومين كمّل. بيفضل لحد ما تقفله بـ ×، حتى لو قفلت اللوحة وفتحتها.
- الطبقة السريعة ليها احتياطي منفصل (TypeSafe أو Vercel)، وتحويلها بيظهر في شريط **أصفر**.
- لو الأساسي والاحتياطي الاتنين وقفوا، المهمة بتقف ورسالة فيها السببين.

## الجلسات

- كل جلسة متخزنة على جهازك (`chrome.storage.local`)، ليها اسم (أول كلمات أول مهمة، وتقدر تغيّره)، وتلاقي كل جلساتك من اسم الجلسة في الهيدر: بحث، إعادة تسمية، حذف.
- **كل تبويب ليه جلسته:** اللوحة الجانبية بتتبع التبويب اللي قدامك. التبويب الجديد بيفتح على جلسة فاضية، والتبويب اللي بدأت فيه مهمة (أو اخترت له جلسة من القايمة) بيفضل على جلسته، وتبويبات مجموعة الجلسة بتعرض نفس الجلسة.
- **مؤشر الوكيل على الصفحة:** وانت بتتفرج، بتشوف مؤشر الوكيل بيتحرك لكل حاجة وبينقر عليها، مع جملة صغيرة بتقول هو بيعمل إيه، وتحديد للعنصر اللي بيشتغل عليه، وإطار منوّر حوالين الصفحة فيه زرار إيقاف. المؤشر مش بيظهر في لقطات الشاشة اللي الموديل بيشوفها، وتقدر تقفله من الإعدادات.
- أكتر من جلسة تقدر تشتغل **في نفس الوقت**. كل جلسة ليها **مجموعة تبويبات** باسمها ولونها، وبتشتغل بس على تبويباتها. تقدر تشوف كل التبويبات، لكن لو تبويب تبع جلسة تانية شغالة بيترفض.
- الوكيل ما بيجيبش التبويب لقدام وانت شغال في تبويب تاني. Chrome بيبطّأ التايمرز في التبويبات اللي في الخلفية، فبعض الصفحات ممكن تبقى أبطأ شوية.

## نسخة احتياطية للإعدادات

**نسخة أوتوماتيك في Google Drive:** لو سجّلت دخول بجوجل، الإعدادات والمفاتيح وتوكنز تسجيل دخول الحسابات (ChatGPT / Claude / Grok) بيتعملهم نسخة في فولدر مخفي (`appDataFolder`) في Drive بتاعك بعد كل تغيير، والإضافة دي بس تقدر تشوفه. لو شلت الإضافة ونزّلتها تاني وسجّلت دخول بنفس الحساب، كل حاجة بترجع أوتوماتيك. لو الإضافة متظبطة أصلاً، ما بتتغيّرش لوحدها، وفيه زرار "استرجع من Drive" في قايمة الحساب. ده نسخة احتياطية مش مزامنة: لو جهازين متسجّلين بنفس الحساب، آخر واحد اتغيّر هو اللي في Drive. النسخة فيها المفاتيح من غير تشفير، ومحمية بحساب جوجل بتاعك. تقدر تمسحها من Drive ← الإعدادات ← إدارة التطبيقات. محتاج **Google Drive API** يكون متفعّل في مشروع Google Cloud، وصلاحية `drive.appdata` تكون مضافة في شاشة الموافقة.

Chrome بيمسح كل بيانات الإضافة لو **شلتها** (Remove). استخدم ↻ (Reload) بدل ما تشيلها، أو نزّل نسخة احتياطية من الإعدادات واستعيدها بعد التركيب. الملف فيه مفاتيحك وتوكنز تسجيل دخول الحسابات (ChatGPT / Claude / Grok)، فخليه عندك. رقم الإضافة ثابت (`bhoimdlegicacjkholpfcokajpiimbcn`) مهما كان الفولدر.

## التثبيت

1. افتح `chrome://extensions` وفعّل **Developer mode**.
2. اضغط **Load unpacked** واختار فولدر الريبو (اللي فيه `manifest.json`).
3. اضغط أيقونة الإكستنشن (أو `Alt+Shift+A`) — اللوحة الجانبية هتفتح على الإعدادات.

## ربط الحسابات والاشتراكات (ChatGPT / Claude / Grok)

1. من الإعدادات اختر المزوّد المطلوب وطريقة الدخول بالحساب (ChatGPT أو Claude أو Grok).
2. **ChatGPT:** اضغط **تسجيل الدخول بحساب ChatGPT** — تُفتح صفحة `auth.openai.com/codex/device`، وسجّل الدخول واكتب الرمز الظاهر في اللوحة (أو استورد `auth.json` من Codex CLI).
3. **Claude:** اضغط **تسجيل الدخول بحساب Claude** — تُفتح صفحة claude.ai، وسجّل الدخول ووافق على الطلب، ثم يظهر لك رمز (شكله `code#state`): انسخه والصقه في خانة الرمز في اللوحة واضغط **إرسال الرمز**. وإن كنت لا تريد استخدام الحساب، فاختر **مفتاح Anthropic API** في القسم نفسه.
4. **Grok:** اضغط **تسجيل الدخول بحساب Grok** — تُفتح صفحة `auth.x.ai`، وسجّل الدخول واكتب الرمز الظاهر في اللوحة. وإن كان لديك مفتاح xAI، استخدمه من الإعداد المسبق **xAI (Grok)** بدل الحساب.
5. بعد نجاح الاتصال، تُحمَّل قائمة الموديلات ومستويات التفكير تلقائيًا.

يحفظ كل تسجيل دخول توكنه في `chrome.storage.local` على جهازك، ويستخدم المزوّد الاحتياطي تسجيل الدخول نفسه، فلا حاجة إلى تسجيل دخول آخر.

## الأدوات التي يستخدمها الوكيل

`read_page` · `navigate` · `web_search` · `click` · `click_at` · `type_text` · `press_key` · `select_option` · `hover` · `scroll` · `get_text` · `screenshot` · `history` · `wait` · `list_tabs` · `switch_tab` · `open_tab` · `close_tab` · `run_javascript` (اختياري) · `ask_user` · `done`

- يتم النقر والكتابة عبر Chrome DevTools Protocol (`chrome.debugger`)، فتكون أحداثًا حقيقية كالتي يصدرها المستخدم، وتعمل على المواقع التي تتجاهل الأحداث المصطنعة.
- قبل الشراء أو الدفع أو إرسال الرسائل أو حذف البيانات أو كتابة كلمات المرور، **يجب** أن يسألك الوكيل وينتظر موافقتك (`ask_user`).
- يُعامَل محتوى الصفحات على أنه بيانات لا أوامر (حماية من prompt injection) — وهذه حماية على مستوى الـ prompt وليست ضمانًا كاملًا.

## أمور يجب أن تعرفها (بصراحة)

- **استخدام اشتراكات وحسابات الذكاء الاصطناعي (مثل ChatGPT وClaude وGrok) خارج التطبيقات الرسمية منطقة رمادية.** تتصل الإكستنشن بواجهات الحسابات وواجهات OAuth مباشرة دون رعاية رسمية من أصحابها. وأي مزوّد قد يغيّر واجهاته في أي وقت، والاستخدام يُحتسب ضمن حدود خطتك.
- **يتطلب تسجيل الدخول إلى Claude لصق الرمز** الذي يظهر في Claude بعد الموافقة. تفتح الإكستنشن الصفحة بنفسها (لأن رابط التفويض يحتوي على PKCE verifier لا يجب أن يصل إلى اللوحة)، ويُستخدم الرمز مرة واحدة فقط وينتهي بانتهاء صلاحيته.
- **لم يُتحقق بعد من مسار حساب Grok على حساب SuperGrok / X Premium حقيقي** — النقل المستخدم هو نفسه الذي تستخدمه pi-ai، ولكن لم تُجرَ تجربة عملية على حساب حيّ.
- **تُبنى مسارات الاتصال بالحسابات وتُختبر بعناية**، وتظهر أي أخطاء أو تجديد للتوكنز مباشرة في الواجهة.
- لما الوكيل يشتغل، كروم بيظهر شريط "Postora Browser Agent started debugging this browser" — ده طبيعي ومطلوب لـ `chrome.debugger`.
- كروم مش بيسمح لأي إكستنشن يتحكم في صفحات `chrome://` و Chrome Web Store.
- التوكنز ومفاتيح الـ API متخزنة في `chrome.storage.local` على جهازك (مش متشفرة) ومش بتتبعت لأي حد غير المزوّد اللي اخترته.
- `run_javascript` مقفول افتراضيًا لأنه بيدي الموديل صلاحية كاملة على الصفحة.

الـ checkout بيستخدم نهايات سطر LF على كل المنصات، عشان أي اختبار بيقرأ ملف مصدري يشوف نفس البايتات اللي بيشوفها CI. لو الكلون بتاعك على ويندوز اتعمل قبل القاعدة دي، هيفضل فيه CRLF وGit هيبلّغ إن كل ملف متتبّع اتغيّر. صلّحها مرة واحدة:

```bash
git checkout -- .    # اكتب الملفات المتتبّعة من جديد بنهايات سطر LF
```
